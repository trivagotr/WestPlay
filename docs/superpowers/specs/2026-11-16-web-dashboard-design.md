# Web second-screen design

User approved web-only side panels on 16 November 2026 and explicitly requested implementation. The in-game cabin UI and APK are unchanged. GPS already presents route/arrival/next-target information: do not duplicate it in large cards. Retain the existing video/control surface at a smaller desktop/tablet size; add compact vehicle state and experimental nearby Convoy visualization alongside it. Narrow screens stack panels. Dark, restrained instrumentation, readable touch targets, explicit unknown/off distinctions.

Approaches: changing the cabin layout affects the in-game tablet and was rejected by the user; independent authenticated web panels reuse the video stream and are selected. My implementation choices: POST snapshot at 2 Hz, 2 s expiry, isolated opt-in 120 s native read-only Convoy probe, nearby spatial plot plus distance list (not markers pasted onto a video whose camera projection is unavailable). No player names.

Use existing official SDK telemetry for cruise, parking brake, fuel, range, lights and engine state. Collect documented wear and warning channels in a separate shared WebVehicle structure; preserve all existing cabin telemetry behavior and rendering. Bump shared bridge version consistently, rebuild app/plugin, but never install into or start the game during development. Missing channels are nullable, never zero/false by default. Coaches satisfaction, per-stop lateness and lane assistance are unsupported until a genuine source is found; show capability notice rather than invented values. Existing GPS remains the route authority.

Native Convoy reader retains exact executable fingerprint gate, read-only rights and bounds, clears absent/ambiguous/stale rows. Own exclusion uses SDK matching. Start only from authenticated web action, bounded 120 s, stop on disconnect, missing host/game or user stop. No automatic process attachment in development. Collect bounded structured logs without pairing token, raw pointers, PIDs, absolute coordinates or names; export on demand. Experimental nearby access is not proof of complete/global roster or actual Convoy membership.

Verification: reducer ownership/stale/bounds tests, unknown-vs-false dashboard tests, authenticated HTTP tests, SDK null/value tests, full remote tests, native helper self-test only, UI build/regressions and responsive browser fixture visual review. Deliver a new runnable build/package while retaining prior package.
